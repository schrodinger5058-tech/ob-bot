## Evidence and reuse decisions
YOLO `src/main.ts` registers ChatView, loads/saves plugin data, registers vault events, and gates desktop capabilities using Platform. `manifest.json` declares mobile support and Obsidian 1.8.7. `src/ChatView.tsx` uses ItemView with React; its mount/reparent machinery is unnecessary for this MVP. `src/core/llm/requestTransport.ts` distinguishes browser/Obsidian/mobile transports and CORS retry detection. `src/core/agent/file-tools.ts` delegates to MCP local-file tools: do NOT copy this desktop execution path. `src/core/paths/yoloManagedData.ts` distinguishes durable data from transient caches and stamps metadata. Reuse lifecycle, view, and durable-state concepts; rewrite UI in plain DOM to reduce bundle and keyboard complexity. Ignore CLI, shell, SDK runtime, MCP server, embedding and module ecosystems.

dsh-bot `plugin/src/types.ts` models stable Bot identity, Room membership with distinct Session IDs, messages with explicit status, context and delegation ancestry. `routing.ts` excludes quoted, fenced, inline-code and email mentions and checks membership. `domain.ts` persists versioned bot/room state with DSH domain storage. `delegation.ts` follows a human root and bounds handoffs; it imports node:crypto and DSH brands, unsuitable here. `history-store.ts` and plugin `index.ts` demonstrate host/storage integration. Reuse separate identities, per-room per-bot sessions, public messages versus private execution state, bounded delegation. Rewrite all adapters; ignore external IM, DSH registrations and Node execution.

Superagent `src/core/model.ts`, `engine.ts`, `assignments.ts`, and docs `002-authorization.md`, `003-execution.md`, `007-architecture.md` separate Ticket mandate, Assignment executor, Session continuity, Policy and Attention. Engine coordinates transactional state through ports; interrupted assignments require explicit recovery. Docs describe worker slots and attention releasing execution slots. Reuse explicit ticket status, parent-child IDs, assigned bot, policy limits and human approval attention. Rewrite a bounded foreground executor with serialized persistence. Ignore shell preparation, repositories/worktrees, deployment environment, source webhooks, background processes and DSH sessions. This is an inspired small implementation, not a port of the research engine.

## Combination
Obsidian Plugin owns lifecycle and a single versioned store. Registry owns independent bot configurations. DM and group membership select isolated sessions. Explicit human @handles route directly; unaddressed group requests ask the lead for a JSON assignment plan, validate membership/limits, call workers separately, then call lead separately to synthesize. Tickets capture each phase and failures. Every LLM tool invocation is checked against the executing bot's scope and permissions; model text never grants authority. No runtime imports from references.

## iPhone risks
No Node, Electron, shell, native filesystem or DSH runtime. Use app.vault and MetadataCache for notes; fetch for streaming APIs, with optional Obsidian requestUrl buffered transport for CORS-sensitive providers. WebKit/provider CORS may block fetch even with a valid key. iOS can suspend or kill execution: save before/after phases and periodically during streams, mark unfinished work interrupted on restart, never automatically replay writes. Foreground-only; no promise of background completion. Scope checks reject traversal, hidden/config paths and non-Markdown targets. All writes need per-operation preview/approval, including append/create. Keys reside in plugin data.json, unencrypted and potentially synced; never log them. Large histories and whole-store saves need later pagination/retention. On-device keyboard, safe-area and networking remain unverified.

## Recommended module map
`main.ts` composition/lifecycle; `ui.ts` home/DM/group/bot forms/settings/approval; `registry.ts` CRUD; `sessions.ts` isolated contexts; `groups.ts` membership and mentions; `orchestrator.ts` routing/tickets/limits; `executor.ts` model/tool loop; `providers.ts` fetch SSE and buffered transport; `tools.ts` vault adapter; `permissions.ts` scope/approval; `storage.ts` serialized snapshots; `types.ts` durable contracts. Test with fake ports without Obsidian runtime.
